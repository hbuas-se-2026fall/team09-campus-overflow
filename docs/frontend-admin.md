# 管理后台前端交接

## 打开页面

在 `frontend` 目录执行 `pnpm install --frozen-lockfile`，然后执行 `pnpm run dev:admin`。打开终端显示的地址后，点击“后台演示”，或访问 `/admin/preview`。不需要演示账号与密码。

演示支持概览统计、问题搜索/状态筛选/分页/详情/确认关闭、用户搜索/角色及状态筛选/分页/资料/停用/恢复。数据均为虚构样本；操作仅保存在内存，刷新或点击“重置演示数据”即可还原，不调用业务 API。

普通 `pnpm run dev` 及生产构建没有演示入口或演示路由。正式 `/admin` 未登录跳转登录；登录后请求 `/api/v1/auth/me` 核验服务端身份，显示“管理后台尚未开放”，不读取本地角色决定权限。

## 后端需要确认的契约

新仓库 main `0983422` 尚未提供管理员角色或管理 API。以下是待协商能力，不是已实现的接口，也不预设路径或响应结构：

| 能力 | 联调需要明确的内容 |
| --- | --- |
| 管理员身份 | `/auth/me` 如何表示权限；管理员如何由服务端授予；禁止公开注册自行选择管理员 |
| 社区统计 | 各指标定义、统计范围、时效性；不能用一页列表长度冒充全站总数 |
| 问题管理 | 搜索、状态过滤、分页；管理员关闭他人问题的授权和审计；已关闭问题的冲突处理 |
| 用户管理 | 用户列表、搜索、角色/状态过滤、停用/恢复；保护管理员自身及最后一个管理员；停用后令牌失效规则 |
| 错误语义 | 401 失效、403 越权、409 状态冲突、422 校验失败以及重试策略 |

现有问题关闭接口仅供提问者操作，未用于后台演示。前端没有新增或修改后端角色、数据库或 OpenAPI。真实接入前需后端更新 OpenAPI，前端再补请求适配、授权入口、列表加载/失败处理和联调测试。

## 验证方式

先运行 `pnpm run build`，再运行 `pnpm run test:e2e`。E2E 同时启动开发演示和生产预览，覆盖既有问答流程、后台交互、身份核验与生产演示隔离。本机使用已安装 Chrome 时，可在 PowerShell 先执行 `$env:PLAYWRIGHT_CHANNEL='chrome'`；CI 自动安装 Chromium。

新仓库使用 `team` 远程，旧仓库 `origin` 保留。交付分支为 `feat/frontend-admin`，供后端核查，不直接合并 main。
